手写单例模式

public class Singleton {

	//注意private，static
    private static volatile Singleton instance;
	//注意private
    private Singleton() {}

    public static Singleton getInstance() {
        if (instance == null) {
            synchronized (Singleton.class) {
                if (instance == null) {
                    instance = new Singleton();
                }
            }
        }
        return instance;
    }
}

手写线程池

import java.util.*;
import java.util.concurrent.*;

public class SimpleThreadPool {

    // 任务队列
    private BlockingQueue<Runnable> taskQueue;

    // 工作线程
    private List<Worker> workers = new ArrayList<>();

    public SimpleThreadPool(int poolSize, int queueSize) {
        taskQueue = new ArrayBlockingQueue<>(queueSize);

        for (int i = 0; i < poolSize; i++) {
            Worker worker = new Worker();
            workers.add(worker);
            worker.start();
        }
    }

    // ================<mark> 提交无返回值任务 </mark>================
    public void execute(Runnable task) {
        try {
            taskQueue.put(task);
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
    }

    // ================<mark> 提交有返回值任务 </mark>================
    public <T> Future<T> submit(Callable<T> task) {
        FutureTask<T> futureTask = new FutureTask<>(task);

        try {
            taskQueue.put(futureTask);
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }

        return futureTask;
    }

    // ================<mark> Worker </mark>================
    private class Worker extends Thread {
        @Override
        public void run() {
            while (true) {
                try {
                    Runnable task = taskQueue.take();
                    task.run();
                } catch (InterruptedException e) {
                    break;
                }
            }
        }
    }
}

#手写HashMap

import java.util.Objects;

public class MyHashMap<K, V> {

    static class Node<K, V> {
        K key;
        V value;
        Node<K, V> next;

        Node(K k, V v) {
            key = k;
            value = v;
        }
    }

    private Node<K, V>[] table = new Node[16];
    private int size;
    private static final float LOAD_FACTOR = 0.75f;

    // hash
    private int hash(K key) {
        return key == null ? 0 : key.hashCode();
    }
    
    // put
    public void put(K key, V value) {
        int idx = (table.length - 1) & hash(key);

        Node<K, V> cur = table[idx];

        while (cur != null) {
            if (Objects.equals(cur.key, key)) {
                cur.value = value; // 覆盖
                return;
            }
            cur = cur.next;
        }

        Node<K, V> newNode = new Node<>(key, value);
        newNode.next = table[idx];
        table[idx] = newNode;

        size++;

        if (size > table.length * LOAD_FACTOR) {
            resize();
        }
    }

    // get
    public V get(K key) {
        int idx = (table.length - 1) & hash(key);

        Node<K, V> cur = table[idx];

        while (cur != null) {
            if (Objects.equals(cur.key, key)) {
                return cur.value;
            }
            cur = cur.next;
        }

        return null;
    }

    // resize
    private void resize() {
        Node<K, V>[] old = table;
        table = new Node[old.length * 2];
        size = 0;

        for (Node<K, V> head : old) {
            while (head != null) {
                put(head.key, head.value);
                head = head.next;
            }
        }
    }
}

}

面试真题

栈模拟队列，如何实现，栈最少需要几个元素，2个栈都是5个元素的话，是否可以，有哪些场景会出问题

1. 如何实现：双栈法

栈是“后进先出”，队列是“先进先出”。要实现顺序的翻转，必须使用两个栈：

  • 输入栈 (Stack In)：负责接收新插入的数据（push 操作）。
  • 输出栈 (Stack Out)：负责弹出数据（pop 操作）。

核心逻辑：

  1. 入队：直接压入 Stack In。
  2. 出队：
    • 如果 Stack Out 不为空，直接从 Stack Out 弹出栈顶元素。
    • 如果 Stack Out 为空，则将 Stack In 里的所有元素逐一弹出并压入 Stack Out，然后再从 Stack Out 弹出。
    • 原理：数据从 In 到 Out 的搬运过程，正好实现了 LIFO 到 FIFO 的翻转。

2. 栈最少需要几个元素？

这是一个理论边界问题：

  • 最少需要 2 个栈：单栈无法改变数据的先后顺序（除非利用递归产生的系统栈，但那本质上还是利用了栈）。
  • 每个栈的容量：
    • 如果只谈“能否实现模拟”，栈的容量最少可以是 1。
    • 如果栈容量为 1，那么这个队列的总容量就是 2（In 存一个，Out 存一个）。

3. 如果 2 个栈都是 5 个元素，可以实现吗？容量是多少？

可以实现。
这种情况下，模拟出来的队列逻辑最大容量是 10。

模拟过程演练：

  1. 连续向队列 push 5 个元素，此时 Stack In 满了（5/5），Stack Out 是空的（0/5）。
  2. 此时执行一次 pop：Stack In 的 5 个元素全部搬到 Stack Out。此时 Stack In 空了（0/5），Stack Out 满了（5/5）。
  3. 关键点：此时 Stack In 又是空的了，你可以继续 push 5 个新元素。
  4. 最终状态：Stack In 有 5 个，Stack Out 有 5 个。队列里一共存了 10 个元素。

结论：逻辑容量 = Stack In 容量 + Stack Out 容量。

4. 哪些场景会出问题？（面试核心加分项）

虽然逻辑容量是 10，但在实际操作中，如果不满足特定条件，会发生**“阻塞”或“溢出”**：

场景 A：入队阻塞（In 满但 Out 不为空）

  • 现象：假设 Stack In 已经装了 5 个元素，此时你想 push 第 6 个。
  • 问题：由于 Stack Out 此时不为空（比如里面还有 1 个旧元素没被 pop 走），根据 FIFO 原则，你不能把 In 里的数据搬到 Out（否则会导致顺序错乱）。
  • 后果：此时虽然队列总数没到 10，但由于 In 栈物理空间满了，且无法“泄洪”到 Out 栈，导致第 6 个元素无法入队。
  • 工程意义：这说明模拟队列的入队能力受限于 Stack In 的瞬时可用空间。

场景 B：搬运时的原子性问题

  • 问题：当 Out 为空触发搬运时，必须一次性把 In 里的所有元素全部倒过去。
  • 错误操作：如果搬了一半停止了，或者中途又有新元素进入 In 且在搬运未完成时就参与了 Out 的弹出，会导致队列内部的数据顺序彻底混乱。

场景 C：空队列异常

  • 现象：当 Stack In 和 Stack Out 同时为空时。
  • 问题：此时执行 pop 操作。
  • 后果：程序必须有抛出 NoSuchElementException 或返回 null 的处理逻辑，否则会触发底层栈的 EmptyStackException。
