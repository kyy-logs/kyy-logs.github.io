  2. 你是偏 AI 智能体方向，还是传统后端？
    • 答题策略：两者都可以，相辅相成。AI 提效需要传统后端的并发与高可用底子兜底；传统项目也需要 AI 来降本增效。
  3. 如果拿到一个 Web 新需求，你的开发流程是怎样的？
    • 答题策略：需求对齐 → 数据库表设计与接口契约 → 架构设计与方案评审 → 编码（含异常、日志）→ 自测联调 → Code Review、上线。

2. 核心实习经历：滴滴现金贷

2.1 核对智能体建设
  1. 智能体解决什么痛点？
    • 回答提示：上下游数据模型理解成本高；人工写脚本覆盖率不足。
  2. 智能体的形态和运行机制是什么？
    • 回答提示：内部网页工具，开发人员手动配置。底层是直接调模型 + 复用已有 Agent 框架（Harness）+ 业务编排。
  3. 谁负责执行核对？
    • 回答提示：AI 负责生成规则或脚本，确定性的代码或引擎负责执行校验，人做最终 Review。
  4. 准确率怎么保障？
    • 回答提示：Prompt 与模板约束 → 静态语法与字段校验 → 自动化回归测试集 → 人工抽检兜底。
  5. 踩过什么坑？错误回传缺失如何处理？
    • 问题：工具执行失败未通过协议回流，服务端没感知。
    • 修复方案：补齐错误回传，让服务端识别后触发智能体重新规划任务。
    • 类比：Java 里吞异常并返回默认值。
2.2 墨西哥放款链路改造与账务迁移
  1. 项目背景是什么？
    • 回答提示：两个服务核心能力归一，数据模型归一但数据源未归一（跨库），原有 MQ 异步流转。
  2. 问题现象是什么？
    • 回答提示：放款成功后查询报错，出现偶发告警，交易状态机查不到数据。
  3. 如何排查？
    • 回答提示：通过 Trace 和日志定位到 MQ 消费存在延迟，产生“数据可见性的时间窗口”。
  4. 如何通过事务编排解决问题？产生了哪些衍生问题？
    • 可见性延迟：将 MQ 消费者写的第二个事务，提前到放款接口的同步链路中。
    • 并发冲突：同步与异步链路并发写。Redis 分布式锁（Redisson 看门狗续期）防并发，借据单向状态机做乐观锁 CAS 兜底。
    • 同步写失败：主事务内包本地消息表，失败后发 DDMQ 异步补偿兜底。
  5. 账务迁移中的异常如何处理？
    • 回答提示：迁移分前、中、后三种状态。迁移中回调采取“收单”持久化，不走后续流程；极端逾期流水告警卡单走人工，正常状态重跑迁移主流程。
  6. 如果锁没释放导致死锁怎么办？
    • 回答提示：Redisson 超时自动释放防永久死锁；上游交易告警发现卡单；依靠唯一索引、乐观锁保证数据不脏；人工介入处理。

3. 个人项目：在线教育平台

3.1 赛季积分排行榜设计
  1. 排行榜用什么数据结构？如何更新和查询？
    • 回答提示：Redis ZSet，key 隔离赛季；ZINCRBY 更新，ZREVRANGE 查榜，ZRANK 查排名。
  2. 底层为什么用跳表，不用红黑树？
    • 回答提示：实现简单、范围查询快、并发友好，利用 span 支持 O(log N) 排名。
  3. 同分怎么排？
    • 回答提示：默认按 member 字典序；优化方案是 score 拼时间戳，或单独算并列名次。
  4. 赛季切换机制是什么？
    • 回答提示：XXL-JOB 子任务串联，建新表 → 分片广播持久化 Redis 榜 → 删除旧榜。
  5. 旧榜如何清理？
    • 回答提示：先冻结只读 → 结算快照 → 发奖对账 → 归档 → UNLINK 显式清理，TTL 兜底。
    • 注意：Redis 过期 key 采用惰性删除和定期删除机制，不会立刻释放内存。

4. Java 基础与并发

  1. 对象的生命周期是什么？
    • 回答提示：创建（类加载、分配内存、TLAB）→ 使用 → 不可达（可达性分析）→ GC 回收；finalize 不靠谱。
  2. HashMap（JDK 8）的结构和原理是什么？
    • 回答提示：数组 + 链表 + 红黑树；转红黑树用于防碰撞攻击；扩容时高低位拆分；线程不安全。
  3. ConcurrentHashMap（JDK 8）的结构和并发机制是什么？
    • 回答提示：放弃 Segment 分段锁，改用 Node 数组 + CAS + synchronized 锁桶头节点；多线程协助扩容（ForwardingNode）；不允许 null 键值。
  4. Java 并发三大特性与 JMM 是什么？
    • 回答提示：原子性、可见性、有序性；Happens-before 原则。
  5. 锁有哪些类型？synchronized 锁什么对象？
    • 回答提示：偏向锁 → 轻量级锁（自旋）→ 重量级锁（OS 互斥）；实例方法锁 this，静态方法锁 Class；Mark Word 存状态。
  6. ReentrantLock 如何实现？有什么特性？
    • 回答提示：基于 AQS 实现；可中断、支持超时、公平或非公平。
  7. 虚拟线程（JDK 21）是什么？适合什么场景？
    • 回答提示：轻量级，由 JVM 调度，适合 IO 密集场景；注意 pinning 问题（synchronized 阻塞），不建议池化；JDK 8 无虚拟线程。
  8. 线程池有哪些模型与拒绝策略？
    • 模型：固定大小、缓存、单线程、定时。
    • 拒绝策略：Abort（默认抛异常）、CallerRuns（反压）、Discard（静默丢弃）、DiscardOldest（丢最老）。

5. 算法手撕题

  1. 二叉树最近公共祖先（LCA）。
    • 普通二叉树：后序遍历递归，左右子树各找到一个则当前为 LCA；时间复杂度 O(N)。
    • 二叉搜索树（BST）：利用有序性，当前值在 p、q 之间即为 LCA；时间复杂度 O(H)，空间复杂度 O(1)。
  2. 双指针对账算法：合并两个有序数组找差异。
    • 两个指针分别遍历两个数组，按字典序比较 id。
    • id 相等时比较金额；不等时，将较小的一方放入“只在左/右”，对应指针后移，最后扫尾。
    • 时间复杂度 O(n+m)，空间复杂度 O(1)（不需要用 HashMap 建表）。

  2. 四个检查指针分别是什么？
    • 考察：测试指针、行为正确性指针、契约性指针等。
  3. 契约性指针怎么判断改动对其他接口或架构有没有影响？
    • 考察：接口契约、调用链、新增逻辑位置。
  4. 改动联动影响识别怎么做？
    • 考察：调用链追踪、影响清单、验证闭环。
  5. 你给阿里开源 Agent 框架提的 PR 主要做了什么？
    • 考察：前端工具失败在 UI 协议层被静默丢弃。
  6. 你是怎么发现这个问题的？当时是什么场景？
    • 考察：响应体没正确组装错误信息，服务端无感知。
  7. 你具体怎么改的？
    • 考察：失败分支补齐错误字段组装和透传，服务端可感知并重试。

6. 技术视野与开放性问题

  1. AI 时代的开发和传统开发有什么很不一样的地方？
    • 考察：写代码变便宜，判断和验证变贵；工程底子仍是根本。
  2. 你以没有经验的身份做判断，判断依据是什么？怎么确保判断正确？
    • 考察：事实兜底、测试回归、清单交叉验证、找导师确认。
  3. 如果进来让你做 Go 语言相关，你能接受吗？怎么快速上手？
    • 考察：语言开放性、学习能力、工程能力可迁移。
  4. 后端开发和 AI Agent 开发有什么区别？市场上对这两者的需求你怎么看？
    • 考察：技术视野、岗位理解、自身定位。
  5. 你更想投后端还是 Agent 方向？
    • 考察：求职方向是否清晰。
